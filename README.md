# План поступления — офлайн-планировщик

Живая страница: **<https://stellasdeutsch-dev.github.io/ai-roadmap-demo/>**

Интерактивный план поступления в вуз: анкета → пошаговый таймлайн с дедлайнами
и отмечаемыми чек-листами → чат-ассистент. Всё — от генерации плана до чата —
работает прямо в браузере: без сервера, без сети, без ключей API и без
регистрации. Единственное хранилище — `localStorage` этого браузера, поэтому
в интерфейсе есть экспорт/импорт плана в файл: это не опция, а способ не
потерять план при очистке данных браузера или переходе на другое устройство.

## Запуск

Статические файлы, сборка не нужна.

```bash
python3 -m http.server 8080
# либо любой другой статический сервер — npx serve, php -S и т.п.
```

Открыть `http://localhost:8080`. Открыть `index.html` напрямую с `file://`
тоже работает, но ES-модули (`<script type="module">`) в некоторых браузерах
требуют HTTP — если страница пустая, запустите локальный сервер.

## Что это может и чего не может

**Может:**
- построить пошаговый план по анкете, с дедлайнами, посчитанными в обратном
  порядке от даты начала учёбы (`intakeDate`) — если дата не указана, вместо
  придуманных дат показываются только текстовые ориентиры;
- показывать блок «что делать сейчас»: просроченное, ближайшее по срокам и
  шаги, у которых срок задаёт вуз и его надо выяснить;
- открывать каждый шаг отдельной страницей (`#/step/<id>`) с развёрнутым
  разбором: порядок действий, что подготовить, где обычно теряют время,
  связанные шаги и переход к предыдущему/следующему. Ссылка на шаг
  открывается напрямую и переживает перезагрузку;
- отмечать выполненные пункты внутри чек-листа каждого шага, а не только
  статус шага целиком;
- редактировать, добавлять и удалять шаги;
- сохранять план в `localStorage` и переживать перезагрузку страницы;
- экспортировать план в JSON-файл и импортировать его обратно (в т. ч. на
  другом устройстве);
- показывать все дедлайны на странице календаря (`#/calendar`): месячная
  сетка, перенос дедлайна перетаскиванием мышью или полем даты в карточке
  дня (работает пальцем и с клавиатуры);
- выгружать дедлайны в файл `.ics` с чек-листами в описании и напоминанием
  за неделю — открывается Google Calendar, Apple Calendar, Outlook;
- скачивать план готовым PDF-файлом (шрифт встроен, текст выделяется и
  ищется) и делать резервную копию в `.json` для переноса на другое
  устройство;
- отвечать на вопросы в чате поиском по данным самого плана: «что дальше»,
  «сколько осталось», «когда виза», «зачем нужен апостиль», вопрос про любой
  шаг словами из его заголовка или чек-листа.

**Не может и не притворяется, что может:**
- проверять требования и дедлайны по реальному сайту конкретного вуза —
  план собран по шаблону, все шаги честно помечены как «общая практика»,
  а не подтверждённые данные;
- отвечать на вопросы, ответа на которые нет в самом плане. Чат — это поиск
  по плану с несколькими правилами (`js/assistant.js`), а не языковая модель:
  на «какая погода в Дельфте» он честно скажет, что не нашёл такого шага,
  а не сочинит ответ.

## Как включить настоящий AI

В этом же проекте есть Node.js-сервер, который умеет то же самое, но с
настоящим вызовом Claude (`claude-opus-5`): реальный поиск по официальному
сайту вуза через `web_search`, структурированная генерация плана и чат с
памятью, который сам предлагает обновления плана. Он лежит рядом, в каталоге
`../roadmap-ai/` этого репозитория с проектами, и не публиковался отдельно —
поднять его может тот, у кого есть ключ Anthropic API:

```bash
cd ../roadmap-ai
export ANTHROPIC_API_KEY=...
npm install
npm start
```

Так делать веб-версию (эту страницу) нельзя: публичная статическая страница
не может безопасно хранить секретный ключ — он был бы виден любому через
«Просмотр кода страницы». Серверная версия должна работать за бэкендом,
который держит ключ при себе (например, Render, Railway, Vercel Functions —
куда угодно, что умеет запускать Node.js и хранить переменные окружения).

## Структура

```
index.html
sw.js             офлайн-кэш: сначала сеть, без сети — копия
css/app.css
fonts/            Inter для страницы и подмножества для PDF — локально
js/
  site.js         название, адрес, ключ хранилища — своё у каждого сайта
  plan.js         фазы, шаблон шагов, сроки от начала учёбы, поля анкеты
  content.js      тексты шагов и ссылки на первоисточники
  utils.js        экранирование, даты — без состояния
  store.js        localStorage: версия схемы, миграции, безопасная запись
  sanitize.js     проверка плана из файла и хранилища перед выводом
  steps.js        статус, прогресс, перестройка плана по новым ответам
  intake.js       анкета и «Изменить ответы», ошибки у полей
  timeline.js     список шагов, «что делать сейчас», правка шагов
  stepview.js     страница отдельного шага
  calendar.js     календарь сроков
  chat.js         выдвижная панель помощника
  assistant.js    ответы помощника по данным плана (правила, не модель)
  exporter.js     файл плана, .ics, загрузка PDF
  pdf.js          сборка PDF без библиотек
  app.js          оболочка: экраны, маршруты, меню, резервная копия
tests/
  core.test.mjs   модульные тесты ядра (npm test)
  smoke.mjs       сценарий в настоящем Chrome (npm run smoke)
```

## Общее ядро и тесты

Всё, кроме `js/site.js`, `js/plan.js`, `js/content.js`, `index.html` и
`tests/fixtures.mjs`, — общее ядро. Каноническая копия — в
[austria-way](https://github.com/stellasdeutsch-dev/austria-way), оттуда
оно копируется скриптом и проверяется на совпадение:

```bash
../austria-way/scripts/sync-core.sh --check
```

```bash
npm test
```

```bash
npm run smoke
```

`smoke` открывает сайт в Chrome без интерфейса и без звука и проходит
основной сценарий: пример, отметки, «Изменить ответы», чат, календарь,
телефон, вредоносный файл плана, открытие без сети. Оба набора тестов
запускает GitHub Actions на каждый push.
